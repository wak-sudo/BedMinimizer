# BedMinimizer

A collection of tools for solving the problem of **Minimization Modulo a Bounded Edit Distance (MIN-BED)** [1].

# Releases

See the release page.

# How to Use

## Apps

### Main Apps:

- **GenCodingApp** – generates a problem instance as a SAT encoding, based on the provided data.

- **CertMakerApp** – generates a certificate in JSON format, based on the SAT results and the instance information file generated by `GenCodingApp`.

- **VerifierApp** – takes a certificate generated by `CertMakerApp` for the found solution and performs its independent verification for correctness.

### Helpers:

- **DfaToDotApp** – converts the project's internal DFA format into the `.dot` format, enabling graphical visualization of the object. Creates a `resDfaDot.dot` file.

- **ClassicMinimizeApp** – performs classic minimization of a DFA stored in the project's format. Creates a `minimized.json` file.

- **DfaGenApp** – accepts the number of states of the target automaton, the number of strongly connected components (SCCs), the SCC depth and the alphabet size. Based on these parameters, it generates an automaton in JSON format that satisfies the specified requirements. If generation fails after a specified number of attempts, the application returns an error. Otherwise creates a `generatedDfa.json` file.

## Automaton Representation

The automaton in the project is represented as a JSON object containing its states, alphabet size, initial state, accepting states, and transition function.

```json
{
  "states_count": 3,
  "alphabet_size": 2,
  "initial_state": 0,
  "accept_states": [2],
  "transitions": [
    [1, 0],
    [2, 1],
    [2, 0]
  ]
}
```

The `transitions` field contains the transition table, where each row represents a state and each column corresponds to an input symbol.

For example, the first element in `transitions`, at index 0, is `[1, 0]`, which means that `𝛿(0, 0) = 1` and `𝛿(0, 1) = 0`. Similarly, the next row, `[2, 1]`, means that `𝛿(1, 0) = 2` and `𝛿(1, 1) = 1`.

## Steps

1. Prepare your automata in the required format.

2. Pass its file path to `GenCodingApp` together with an expected maximal number of states of the output automaton.

3. A `problem.sat` file for the solver will be created, together with an `instanceInfo.json` file is required at a later stage.

4. Pass `problem.sat` to the SAT solver of your choice. **Important:** print/save the results using the `-q` flag.

5. If the solver finds a solution, pass its results together with `instanceInfo.json` to `CertMakerApp`.

6. The following files will be created:

   - `output_dfa.json` – contains the resulting automaton in JSON format.
   - `certificate.json` – contains information that enables fast and independent verification of correctness.

7. `certificate.json` can be passed to `VerifierApp` to verify its correctness and reduce the likelihood of false positives.

# Technical Details

## Requirements to Build

The following tools are required to build the project:

- `make`
- `cmake >= 3.16`
- `git` 
- a compiler supporting **C++20** (for ex. `g++`)

Other dependencies will be installed and built by CMake.

To install these dependencies on a system with the `apt` package manager:

```bash
sudo apt install make cmake g++ git
```

## Building

Run `make` in the root folder. 

## Modules

The project is split into several modules:

- **AugScc** – takes the input automaton and, based on it, constructs a graph of strongly connected components (SCCs) satisfying the required properties. The module also provides access to resources that enable the efficient use of precomputed results during the generation of the encoding.

- **CodeGen** – responsible for generating the encoding based on any object satisfying the precomputation requirements, specifically an object of type `AugScc`. The module also takes into account a specified maximum number of states for the resulting automaton. The generated encoding can be exported to a file.

- **Logic** – a `CodeGen` submodule responsible for providing the tools required to efficiently construct the encoding. It offers, among other utilities, implementations of bit vectors, pseudo-Boolean operations, structures representing CNF formulas, mechanisms for converting formulas to the DIMACS format, logical expression syntax, and an implementation of the Tseitin transformation.

- **CertReader** – takes the result returned by the solver, together with the original variable assignment, and processes it into an organized result structure.

- **Verifier** – responsible for verifying the correctness of the received certificate. It acts as an additional layer of protection against implementation errors, particularly false positives. The module also facilitates the debugging process and enables independent verification of the obtained result, separate from the search process.

- **Serializer** – responsible for the serialization and deserialization of objects in JSON format. The module also enables deterministic finite automata (DFAs) to be exported in `.dot` format, allowing them to be graphically visualized using appropriate software such as Graphviz.

- **Utils** – contains utility functions used globally across the project modules.

- **Shared** – contains header-only definitions of shared structures and contracts.

- **DfaGen** – generates pseudorandom automata with a specified number of states, alphabet size, number of strongly connected components, and the SCC depth. This module can be used to generate test data. Further research is needed.

- **BedMinimizer** – serves as an integration layer for the remaining modules and provides a simplified interface, hiding the details of their internal implementation.
